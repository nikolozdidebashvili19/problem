# T-009 — i18n with next-intl

Phase 0 · Status: **done** · Depends on: 001

## Steps
1. `npm i next-intl`; locales `ka` (default), `en`; routes `/ka/...`, `/en/...` (route groups move under `src/app/[locale]/`).
2. Messages in `src/shared/i18n/messages/{ka,en}.json`; request config in `src/shared/i18n/`.
3. Combine next-intl locale routing with the existing auth checks in `src/proxy.ts`.
4. Date helper in `src/shared/utils/format.ts`: `Intl.DateTimeFormat('ka-GE', { timeZone: 'Asia/Tbilisi' })`.
5. `hreflang` alternates in metadata.

## AC
- No hardcoded UI strings; switching locale keeps the current path.
- Dates render server-side in Asia/Tbilisi (no hydration mismatch).

## Implementation notes
- **Deviation from step 1:** cookie-based locale instead of `/ka`, `/en` URL prefixes. Everyone gets Georgian; the header
  switch (ქარ / EN) sets the `NEXT_LOCALE` cookie (1 year) and refreshes in place. URLs stay unchanged, so no route moves.
  Trade-off: no `hreflang` / separately indexable English pages. Prefix routing can be added later with
  `localePrefix: 'as-needed'` (Georgian stays at `/`) without changing any messages or components.
- Messages: `src/shared/const/messages-ka.const.ts` (source of truth) and `messages-en.const.ts` typed against it, so a
  missing key fails `tsc`. Request config: `src/shared/lib/i18n-request.ts`, registered in `next.config.ts`.
- Bilingual DB names (categories, locations) and status labels pick `nameKa` / `nameEn` by locale (`localizedName`).
- Dates: `formatReportDate(date, locale)` → `1 ნოე. 2026` / `1 Nov 2026`, always Asia/Tbilisi.
- Form validation messages follow the language via zod's built-in `ka` locale (browser only).
- Auth hooks now store error codes (`INVALID_CREDENTIALS`, `EMAIL_TAKEN`, …) that forms translate.
- Not translated: admin `/dashboard` and `(protected)/error.tsx` (staff-only).
- Open: save the choice to `user.locale` for signed-in users (T-028); theme toggle is hidden below `sm` to fit the header.
